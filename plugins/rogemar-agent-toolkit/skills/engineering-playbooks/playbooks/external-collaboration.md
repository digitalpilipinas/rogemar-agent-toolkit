# External collaboration without a second orchestrator

Use only when an external provider offers necessary independent evidence or a
bounded capability the current task deliberately selects. Providers retain their
native methods and supported models within the recorded authority. No automatic
provider installation, authentication, recursive reviewer invocation or expenditure.

For Codex-hosted CLI coordination, use the installed agent-collaboration-terminal
skill and its actual runner contracts. It is a Codex-specific implementation, not a
portable claim that every host has Codex PTY/background APIs. In another harness,
use the native task/terminal controls or a bounded manual handoff when authorized;
record missing automation instead of renaming unsupported calls.

Give one provider the exact candidate/worktree, original outcome, full agreed review
scope, allowed/excluded paths, workspace and external authority, bounded budget,
required output/evidence, and stop conditions. Preserve uncommitted source when that
is the agreed target. Do not quietly replace it with committed HEAD or a summary.
The receiving provider discovers only useful installed capabilities and must verify
its own controls; parent credentials, model choice and approvals are not inherited.

For a selected code-review provider, review the full agreed candidate rather than a
sample. A domain emphasis does not replace coverage. A testing companion is not a
provider review. Keep each provider's initial findings separate; preserve the existing
local and cloud-wave completion barriers before owner reconciliation.

Use independent workspaces for writers and serialize shared resources. The main
owner integrates the actual diff and checks results. Completion requires a terminal
result and the relevant observed artifacts, not a spinner, token percentage, open
terminal or self-authored status line. A timeout or partial report remains incomplete.
Use native completion events/cursors when supported, not repeated unchanged polling.

Reconcile uncertain external actions before retry. Preserve provider limits and
cancellation, and never restart a completed provider merely to fill a template.
Missing required evidence blocks its named gate; optional provider failure does not
block unrelated work. Cross-harness runtime qualification remains separate from
this portable method.
