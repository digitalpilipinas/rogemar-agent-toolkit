# Trigger maintenance across installations

Inspect the loaded skill path, invocation metadata, active global instructions,
plugin origin and surfaced tools separately. Same-name skills are not merged.
Use the installed runtime's discovery/configuration interface when available;
source files alone do not prove what a running session selected.

- Preserve intended explicit-only imports with the receiving harness's supported
  policy. In Codex, `agents/openai.yaml` supports
  `policy.allow_implicit_invocation: false`; retain existing interface/dependency
  fields and native source-harness controls. Do not make ordinary skills
  explicit-only without an actual requirement.
- Path-based disable entries must identify the installed skill. Repair moved
  paths; remove obsolete entries only after identifying the replacement or its
  absence. Verify disabled versus explicit-only behavior separately.
- Resolve scripts/assets from the directory containing the loaded `SKILL.md`,
  not a hardcoded personal installation root. Do not change `CODEX_HOME` to make
  a helper path fit. Helper availability and optional runtime installation are
  separate checks.
- Retire identical duplicate discovery recoverably after full-tree and consumer
  comparison. Use source-qualified routes for intentional adapters or multiple
  provider distributions, preserving unique capabilities. Do not edit managed
  plugin caches to change global routing.
- Preserve provider-owned procedures. In particular, selected CodeRabbit reviews
  use its own skill and full agreed candidate. Routing is not permission to
  install, authenticate, transmit unrelated data or replace a full review with
  another method.
- Keep managed Argent content intact. An owner-maintained compatibility section
  outside it can define cloud fallback and current host tool discovery. Limit it
  to actual Argent tasks: sufficient authorized work may continue when the tool
  is optional and absent; required device evidence stays blocked. Route Chromium
  CDP to the compatible interaction skill, TV to the TV skill, and use the host's
  actual tool-schema discovery capability. Preserve discovery-before-tap, saved
  flow recording and scoped cleanup requirements.

After changes, compare protected entry instructions and descriptions; test fresh
runtime discovery and representative positive/negative requests. Report static,
discovery, provider and device evidence independently. Existing sessions may need
a new turn/session to adopt updated policy; do not claim a live reload from edits.
