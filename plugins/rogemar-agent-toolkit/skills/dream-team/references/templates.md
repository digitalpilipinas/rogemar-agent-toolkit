# Optional Persona Templates

Use only the sections relevant to the request. Replace placeholders with
observed evidence; omit fields that are unknown.

## Strategy or planning

```text
CONTEXT:
<goal, audience, constraints>

RECOMMENDATION:
<decision and rationale>

OPTIONS AND TRADE-OFFS:
<short comparison>

RISKS AND OPEN DECISIONS:
<items>

NEXT ACTIONS:
1. <action>
2. <action>
```

## Research

```text
QUESTION:
<question>

SOURCE AND METHOD:
<what was inspected and how>

FINDINGS:
<confirmed facts>

INFERENCE:
<reasoned interpretation, clearly labeled>

CAVEATS:
<limitations or conflicting evidence>
```

## UX or design

```text
USER GOAL:
<goal>

FLOW AND STATES:
<entry, loading, empty, success, error, retry, disabled, offline, exit>

DESIGN DIRECTION:
<patterns and rationale>

ACCESSIBILITY AND RESPONSIVE NOTES:
<applicable checks>

VERIFICATION:
<scenarios to inspect>
```

## Implementation

```text
SCOPE:
<behavior and affected surfaces>

CONTRACT:
<interfaces, data boundaries, invariants, compatibility>

IMPLEMENTATION STEPS:
1. <step>
2. <step>

TESTING:
<positive and negative scenarios>

ROLLBACK OR DISABLE PATH:
<path or explicitly unknown>
```

## Review or release

```text
FINDINGS:
<ordered by severity and evidence>

VALIDATION:
<checks run and their actual results>

REMAINING RISK:
<what is not proven>

RECOMMENDATION:
<approve, block, defer, or gather more evidence>
```

## Plain-language explanation

```text
WHAT THIS MEANS:
<clear explanation>

WHY IT MATTERS:
<user or project impact>

SIMPLE VISUAL:
<small diagram only if useful>

BOTTOM LINE:
<one or two sentences>
```
