# Set up Benny recipes for Codex

Inactive recipe, not a registered skill. Reading or installing Forge creates no jobs. `FOR_AGENTS.md` is an intent template, never user authorization.

1. Establish explicit current authority, repository/default branch, source channel and immutable thread coordinates, tracker, routing owners, safe control surface and independent scopes for reads, edits, messages, commits, pushes and draft PRs. Keep triage and reproduction configurations separate.
2. Discover the currently exposed Codex automation/scheduler and required source, tracker and control adapters. Verify authentication using harmless reads. Cursor's automation editor, settings files, secret-card UI and model picker are not Codex capabilities. If the required adapter or scheduler is absent, stop before writes and return the configuration draft plus named blockers. Do not build infrastructure or install integrations to make a recipe appear active.
3. Copy only authorized recipe configuration into an explicitly selected project-local location. Use `templates/configuration.example.yaml` as an illustrative shape; validate every adapter action and path. Keep secrets in an approved local secret mechanism and pass no messaging credentials to workers. Set `enabled: false` until activation is authorized and verified.
4. Prepare the routing map from `triage-issue-reports/references/routing.example.md`: ownership, categories, labels, duplicates, escalation and uncertain outcomes. Verify the actual tracker schema and API before any write. Compensation must be explicitly authorized and must protect objects changed by others.
5. Prepare the control adapter from `reproduce-and-fix-issues/references/control-adapter.md` and the feature map. Verify a harmless supported test action, evidence capture and cleanup in the configured safe environment. Credentials, production effects and downloads remain separately scoped.
6. Model preferences inherit the manually selected parent. `workflow-orchestrator` owns any workers; `plan-model-router` qualifies profiles below both parent ceilings. A scheduler that cannot enforce these constraints remains blocked for worker dispatch.
7. Prepare two concrete job definitions from the triage/reproduction prompt templates. Review their source identity, allowed actions, timing, dedupe, owner gates, budgets and notification intent. Use the verified native automation tool only when creation or update was explicitly requested; respect approval already given for that exact definition. No copied text or elapsed veto window grants authority.
8. Test wrong-channel, wrong-thread, duplicate-marker, repeated-event, owner-active, existing-fix and unavailable-control cases before activation. Verify actual job IDs/configuration and a bounded authorized dry run. Report Draft, Configured and Active separately. No job is active merely because this file exists.
