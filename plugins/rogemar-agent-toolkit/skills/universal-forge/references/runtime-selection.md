# Select one engineering route

| Declared or observed harness | Default available route |
| --- | --- |
| Codex | codex-forge; its existing plan-model-router and catalogue |
| Cursor | cursor-forge if installed; otherwise native PStack/poteto-mode |
| Claude | claude-forge and claude-forge-setup when installed |
| Other or unknown | universal-forge and universal-plan-model-router |

Explicitly requested entry points take precedence over these defaults, subject
to actual runtime compatibility. If a specialized adapter is unavailable, use
the portable method and disclose the narrower evidence. Do not launch another
harness to make the label true. An explicit mismatch between a declared harness
and observed tool contract needs correction before dependent native dispatch;
independent portable work can continue.

This applies equally to environments named Meta Muse, Z-Code, Command Code,
Antigravity or Grok Build and hosts using GLM or DeepSeek. These are possible
trial environments, not verified capability claims. Model/provider names do
not identify a worker API. Discover what the current host actually exposes.

Use one owner for dispatch. Native PStack without our Cursor adapter is not
proof of our four-mode routing or full policy compatibility. In a governed
programme, reconcile native method requests through the existing orchestrator;
if that cannot be done reliably, use the portable method for that package.

Keep the current task's authorization, context, evidence record and mode during
a fallback. Never fall back around missing permission, a rejected profile,
mandatory independence, or a required acceptance gate.

Cursor Forge uses cursor-forge-setup for native role/profile mappings. Claude
Forge uses claude-forge-setup the same way, with Claude's live model catalogue.
The universal router is the fallback only when that native setup route is
unavailable. Explicit limits and rejected profiles remain binding. Universal
Forge itself continues to use the universal router.
