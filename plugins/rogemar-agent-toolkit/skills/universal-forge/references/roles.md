# Shared role assignments

Model-free role contracts for portable execution. Choose relevant installed
skills rather than copying their implementations. Group defaults are task-fit
preferences resolved against each host's models, not a universal rank table.
Main-owned roles are parent responsibilities; helpers never take final authority.

| Group | Role IDs |
| --- | --- |
| coordination | `parent-coordinator`, `workflow-coordinator`, `integration-owner`, `findings-consolidator`, `why-synthesizer`, `reflect-synthesizer` |
| engineering | `feature`, `refactoring`, `bug-fix`, `perf-issue`, `hillclimb`, `hardest-tasks`, `how-explorer`, `how-explainer`, `why-investigators`, `reflect-tooling`, `swarm-workers`, `bug-triager`, `goal-scout` |
| design | `judgment-and-prose`, `reflect-divergent`, `arena-runners`, `architect-runners`, `ux-flow-designer`, `ui-designer`, `design-system-reviewer`, `interaction-designer`, `accessibility-reviewer` |
| verification | `validation-runner`, `visual-reviewer`, `browser-qa`, `simulator-qa`, `emulator-qa`, `physical-device-qa`, `qa-runner` |
| review | `how-critics`, `reflect-judgment`, `arena-cross-judge-pool`, `interrogate-reviewers`, `correctness-reviewer`, `scope-reviewer`, `acceptance-auditor`, `goal-judge` |
| operations-learning | `status-monitor`, `learning-curator` |

- parent-coordinator, workflow-coordinator and integration-owner remain main-owned.
  Findings consolidators provide evidence; main retains final reconciliation.
- Goal Scout/Judge reuse GoalBuddy contracts only where those native roles are
  installed and usable. Preserve independence and fixed settings. Otherwise use
  ordinary investigation/review terminology; never relabel it as GoalBuddy proof.
- Design roles select applicable UX, UI, design-system, motion and accessibility
  skills. Permissions come from the bounded assignment, not the role label.
- Browser, simulator, emulator, physical-device and visual evidence remain
  separate. Screenshots alone do not prove interaction or physical-device QA.
- Scope review may use Ponytail; it cannot replace correctness or acceptance.
  Dream Team contributes useful perspectives through the same orchestrator.
- Learning curator activates only for explicit project-learning work. No automatic
  capture, promotion, memory writes, hooks or delivery interruptions.
- Status monitor makes bounded checks; recurring work needs explicit scheduling.
- Writers need explicit owned scope and verification. Reviews, scouts, judges
  and monitors remain read-only unless separately assigned authorized write work.

The existing Codex catalogue retains its tested concrete mappings. This portable
role inventory carries no Codex model defaults and does not change native pins.
