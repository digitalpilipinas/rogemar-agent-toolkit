# Interaction Polish

## Workflow

1. Identify the exact moment being polished: start, choose, submit, sync, recover, share, celebrate, return, or cancel.
2. Check touch/keyboard target size, reach, focus behavior, feedback timing, disabled/loading behavior, and whether the user always knows what happened.
3. Add or refine microcopy that is brief, useful, and domain-native.
4. Treat offline, failed, empty, and destructive states as first-class interactions.
5. Use motion, haptics, and animation sparingly and only when supported by existing app patterns.
6. Verify the polished state on small screens and with slow/failed network assumptions when relevant.

## Tone

- Clear, calm, and action-oriented.
- Celebrate real progress without inventing rewards or social proof.
- Prefer precise action labels over explanatory UI text.

## Output

Provide before/after interaction notes, implementation targets, copy changes, and QA states to test.
