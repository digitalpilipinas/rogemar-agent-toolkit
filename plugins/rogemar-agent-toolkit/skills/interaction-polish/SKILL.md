# Interaction Polish

Own the bounded post-implementation polish pass; keep the current coordinator,
brief and finding record. For an existing web artifact, read
[design-polish.md](references/design-polish.md) for the adapted OpenDesign /
Impeccable audit, critique, polish and hardening method. Review-only requests
produce findings; implementation requests permit the scoped fixes. Motion
implementation or specialized motion review belongs to
`motion-animation-engineer` when that skill is available.

For affected mobile behavior, read [mobile-craft.md](references/mobile-craft.md)
only when relevant. These adapted Appllama methods need no subscription or MCP
and use the existing task owner and evidence record.

When the brief or design system states its tokens, run a quick count before the
visual review: accent hues outside the stated palette, corner radii outside the
stated scale, emoji used as interface icons, gradients with no stated reason, and
duplicate labels for one intent. Each out-of-spec count is a fix or a recorded
exception. Without stated tokens, skip the count; it is not a universal ban.

For web control feedback, tooltip continuity or pointer behavior, read
[web-control-craft.md](references/web-control-craft.md) when relevant.

## Workflow

1. Identify the exact moment being polished: start, choose, submit, sync, recover, share, celebrate, return, or cancel.
2. Check touch/keyboard target size, reach, focus behavior, feedback timing, disabled/loading behavior, and whether the user always knows what happened.
3. Add or refine microcopy that is brief, useful, and domain-native.
4. Treat offline, failed, empty, and destructive states as first-class interactions.
5. Use motion, haptics, and animation sparingly and only when supported by existing app patterns.
6. Verify the polished state on small screens and with slow/failed network assumptions when relevant.

## Tone

- Clear, calm, and action-oriented.
- Celebrate real progress without inventing rewards or social proof.
- Prefer precise action labels over explanatory UI text.

## Output

Provide before/after interaction notes, implementation targets, copy changes, and QA states to test.
