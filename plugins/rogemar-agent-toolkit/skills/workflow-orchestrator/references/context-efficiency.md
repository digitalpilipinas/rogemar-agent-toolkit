# Context efficiency

Apply when large outputs, repeated reads, delegation or a long handoff make
context handling material. Optimize the complete accepted task, including
recovery and verification. This is guidance within the current workflow, not
another checklist, coordinator or gate.

## Load enough for the next decision

Inspect names, data shape or a bounded locator result before requesting a large
payload. Read the relevant source faithfully with the callers and surrounding
contracts needed for correctness. Required instructions still apply. An explicit
range or search scope is useful; an unexplained cutoff is not complete evidence.

Reuse already-loaded, unchanged instructions and facts. Refresh affected context
when source, candidate, board state, authority, preferences or live capabilities
change, or when recovery leaves their identity uncertain. Keep required routing
and capability checks: every justified Forge assignment still needs fresh profile
resolution. A prior passing receipt is evidence only for its recorded scope.

Keep small common rules in the entry skill and substantial conditional detail
in linked references. Do not load the entire family, copy a conversation into
every prompt, or replace a useful local explanation with a chain of references.

## Preserve evidence when shortening output

Preserve source, diffs and arbitrary command results. Group search matches without
silently dropping results. For predictable install, build, test or progress noise,
use a concise result only when it avoids work and the complete original remains
available. Retain command, candidate and environment identity, exit status,
relevant counts, distinct diagnostics, failed/skipped/blocked/deferred checks and
the original log location. Omission or truncation must be visible.

Read saved output before rerunning a command solely to recover hidden text.
Rerun when current evidence is needed or the original is unavailable and the
operation is safe and authorized. A summary is a locator, not a substitute for
the complete intended diff or decisive failure evidence needed for acceptance.
Keep line locations for findings and diffs; avoid decorative per-line prefixes
when the reading or editing operation does not use them.

## Carry focused context between owners

A large payload alone does not justify a worker. Compare independent reasoning
or useful parallel work with prompt, retrieval, coordination and validation cost.
Give workers the outcome, relevant invariants, authority, exact scope, source
pointers, checks and stop conditions. Prefer a focused assignment over full
history when it is sufficient; include important constraints explicitly rather
than assuming a worker can recover the parent's conversation.

Reuse a worker for a coupled follow-up only when its profile, permissions and
contract still fit. Preserve required review independence. Independent work may
run in parallel under the orchestrator's side-effect and isolation rules; shared
writers remain isolated or sequential. Context efficiency changes no model,
permission, review, publication or completion requirement.

Consume a completed result already delivered by the runtime without retrieving
it again. If a notification lacks the result, use the supported retrieval call.
Prefer supported event waits or status cursors to repeated unchanged polling;
do not assume notification batching or change tool-specific wait semantics.

Reuse the existing plan, board and receipts for continuity. Carry the current
task, source/candidate identity, still-applicable decisions and constraints,
relevant dependency evidence, blockers and next action. Load older detail as
needed. A concise view never replaces authoritative state or the full coverage
audit. Native compaction may free space while losing detail; verify critical
state and evidence after uncertain recovery.

## Evaluate the complete workflow

Compare equivalent tasks with the same starting candidate, model/effort and
permissions. Include parent and worker usage, retrieval, retries, recovery and
verification; track acceptance defects as well as time and tool calls. Use actual
input/output and cached-token telemetry when exposed. Missing telemetry leaves
token or cost savings unverified; file size and character estimates are not
billing data. Do not trade away correctness or required evidence for brevity.

Skills cannot guarantee prompt-cache hits, prune the runtime-injected catalog,
defer tool schemas or change native compaction/notifications. Use only observed
runtime support; do not install a wrapper, hook, service or new dependency here.
