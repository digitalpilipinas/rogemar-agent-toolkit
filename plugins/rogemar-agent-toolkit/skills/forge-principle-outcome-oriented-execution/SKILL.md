# Outcome-oriented execution

Keep the original observable outcome as the acceptance oracle. Choose the smallest coherent change that reaches it; do not optimize for an attractive plan, activity count or intermediate artifact. Reassess when evidence changes the causal model. Preserve scope, security and compatibility constraints while experimenting in isolated task-owned work. Verify with the checks and runtime evidence the change requires, rather than imposing every test category universally. Separate implementation, validation, publication, deployment and monitoring states. Unavailable evidence and unmet criteria remain explicit; never lower the goal silently.

Read [the shared Forge runtime](../workflow-orchestrator/references/forge-runtime.md) for authority, delegation, routing and evidence boundaries.
