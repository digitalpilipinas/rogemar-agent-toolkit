# Contract handoff check

Modified from OpenDesign's reference-design-contract checklist, Apache-2.0;
see [provenance.md](provenance.md).

- The artifact, audience and primary task are explicit.
- Reference evidence is identified; observed/provided/inferred claims remain distinct.
- Keep/change boundaries and source-specific reuse limits are clear.
- There is one coherent direction with concrete token, type, layout and component choices.
- Existing product contracts are preserved and missing inputs are visible.
- Responsive, input and accessibility constraints reach the builder.
- The handoff states what the first artifact must prove and what would fail review.
- The output fits the project's documentation shape; no duplicate mandatory document set.

If another builder still needs to guess the audience, source of a design
decision, binding constraints or success condition, finish that part of the
contract before handoff. Do not demand a live preview for a text-only planning
task; report the actual evidence produced.
