# Compatibility and qualification boundaries

Compatibility is a set of evidence-backed capabilities, not one universal badge.
The baseline catalog intentionally distinguishes native entrypoints and portable
methods. Codex origin does not make shared methods incompatible with other harnesses.
Owner-observed working routes are retained. Target lists and model generations are unchanged.

| Surface | Reuse route | Evidence in this candidate |
| --- | --- | --- |
| Planning, quality/testing methods | Existing portable core | Source alignment and new pure-helper tests; complete host trials pending. |
| Codex Forge | Existing Codex entry and model router | Native bindings preserved; live dispatch/parent switching not tested here. |
| Cursor Forge | Existing Cursor adapter/setup, shared methods | Native bindings preserved; live Cursor trials pending. |
| Other catalog-supported harnesses | Universal Forge and shared methods | No invented native tools; runtime trials pending by host. |
| PStack poteto-mode | External Cursor-managed workflow | Remains external and unchanged; copying toolkit files does not install it. |
| External CLI coordination | Existing agent-collaboration-terminal route or native portable handoff | CLI execution and provider review not available in this environment. |
| Workflow, knowledge, lifecycle metadata helpers | Python 3.9+ standard library | Python syntax compatibility and local synthetic tests; host behavior remains separate. |
| Protected observation read | Host supporting the required safe filesystem operations | Comparator fixtures pass only after local tests; OS/CI provisioning not supplied. Unsupported flags fail closed. |
| Knowledge persistence / ingestion | Existing authorized project documentation tools | Playbook, metadata lint and optional live-query/removal adapters; no new storage engine or ACL service. |

For each deployed skill, record the canonical revision, trigger/non-trigger tasks,
required resources, permissions, adapter and actual successful/failed trials.
Installed files, discoverability, authenticated access and executed behavior are
separate. A task needing no native mechanism can use the portable method directly;
a required independent reviewer or device cannot be replaced by a prose fallback.

The coverage record in this directory distinguishes inspected source from metadata
only. `scripts/alignment_inventory.py` joins it to an actual checkout and reports
unreviewed or changed bodies without fabricating audit completion. Reading and
hashing a file mechanically is not a semantic review of it.

Keep adapters thin and canonical resource paths intact. Preserve existing per-file
licenses and the external/native package boundaries. Provider or host version
changes require relevant requalification; neither legacy results nor the name of a
successor model establishes equivalent behavior. Shared method improvements must
not be implemented by editing runtime-owned plugin caches.
