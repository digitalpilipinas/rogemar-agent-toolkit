## Architecture and portability

Keep one planner (`create-plan`), one dispatcher (`workflow-orchestrator`), one
execution entry (`codex-forge`, `cursor-forge`, or `universal-forge`), one Integrated
Workflow acceptance record and one Project Learning writer. Helpers extend those
owners. They do not create a scheduler, secondary authority system or memory service.

Codex catalog origin is not evidence of method incompatibility. Existing owner-
observed use in Cursor/other harnesses is preserved. Original instructions and
native commands remain available; portable fallbacks fill actual capability gaps.
Do not duplicate every leaf into a new universal family or rewrite target eligibility
without an installation need. The routing index is generated from the canonical
catalog and shipped unchanged with selected packages; uninstalled entries describe
possible routes, not available tools. `select_methods.py` resolves actual files.

## Rollout and recovery

The source change can be reviewed and merged with its explicit qualification limits.
It does not enroll any host in the stronger protected-execution tier. That tier
requires a separately controlled policy, trusted producer/verifier and actual native
permission/cancellation trials before use. Preserve the unqualified state until then.

The coupled routing, learning and boundary changes stay in one coherent PR so no
intermediate package advertises missing helpers. Revert the reviewed commit through
normal Git review if needed; preserve unrelated work and learning history. Staged
instruction changes have their own hash-bound, group-scoped rollback. No live
repository protection or account changes are included.
