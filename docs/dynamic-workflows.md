# Dynamic workflow adoption

This update adds a conditional method to the existing orchestrator, not another
delivery workflow. Use it for a broad audit, independent migration packages or an
actual failing-check backlog when coordination earns its cost. Small corrections
stay on the ordinary route. Global instructions and unrelated domain skills do
not need to be rewritten.

The method is in
`plugins/rogemar-agent-toolkit/skills/workflow-orchestrator/references/dynamic-workflows.md`.
Integrated Workflow, planning, Swarm and shared Forge/playbook routes point to it.
Claude Forge adds native workflow authoring/permission/profile guidance. Other
harnesses retain their own model controls and worker tools. No provider, session
mode, authentication, watcher or native runtime script is installed automatically.

## Qualification boundary

The owner narrowed this update to local skills and repository sources: do not
launch or authenticate Claude for this delivery. The live pilot is deferred.
Source/contract tests do not prove native workflow execution, quality or cost gains.
When separately authorized, begin with `scripts/`, two investigation packages,
two independent package reviewers and two finding challengers. Four phases:
candidate/preflight, investigation, full package review, challenge/reconciliation.
Six planned workers plus the parent; at most ten total including replacements
and the parent, two active workers, no nested spawning. Stop after two consecutive
rounds without verified progress, or earlier on completion, blocker or budget.
Audit targets remain read-only; isolated test fixtures require explicit scope.

## Install and verify

Use the managed installer from the reviewed checkout and the target harness's
existing selection. Inspect the dry-run, preserve local modifications and external
skills, apply the upgrade, then verify hashes/resources with scoped `doctor`.
An instruction update does not require a service login.

For an existing cloud environment, execute the same dry-run/upgrade and verification
inside that environment. Use its actual harness; do not assume a local home directory
or recreate the project. Preserve existing setup steps and credentials. Record the
source revision, installed hashes, resource presence and observed skill discovery
separately. GitHub publication is not VM installation or active-session discovery.
An unreachable environment remains unverified; do not claim synchronized agents.
