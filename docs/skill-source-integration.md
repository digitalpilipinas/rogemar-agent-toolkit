# Imported skill sources and local adaptations

`catalog/imported-sources.json` records exact upstream revisions and original file
hashes. The normal skill lock records adapted, distributable content. These are
separate evidence: an upstream hash is not a claim that the adapted file is identical.
Upstream MIT notices remain with all twelve Swift skills and Codebase Design.
TesterArmy preserves its Apache-2.0 license and NOTICE from the published release.
The twostraws collection repository is a discovery directory, not another skill.
Nested plugin wrappers were excluded; each skill has one discoverable SKILL.md.

## Selection and distribution

The `swift` pack contains four twostraws review/domain methods, AvdLee's SwiftUI
and concurrency methods, and six cooperating Xcode build methods. `ios` and the
full profile include all twelve. The six-skill core profile remains unchanged.
Codebase Design belongs to engineering; TesterArmy belongs to web/mobile.
All methods are portable files. macOS/Xcode/device requirements apply to execution,
not to reading their instructions on Linux or in a cloud environment.
Required resource paths are cataloged and checked in source and release packages.
External recipe entries are included in the generated routing index as discovery
metadata; missing external files remain unavailable, not implicitly installed.

## Compatibility adaptations

- Preserve the project's actual Swift/compiler/SDK targets, UIKit integration,
  persistence architecture and test conventions. New SDK examples require
  availability checks. SwiftData and XCTest migration are never assumed preferences.
- Use AvdLee SwiftUI/concurrency for implementation and diagnostics, and twostraws
  for focused reviews where useful. Loading both needs a concrete coverage reason.
- Xcode remains a specialist under the existing dispatcher. Reuse task approval;
  do not create another delivery owner or mandatory approval/reviewer panel.
- Benchmark builds use run-owned temporary DerivedData. A supplied path is a parent,
  never an erase target. Only supported non-path settings can be forwarded.
  All executed phases leave logs, and failure/timeouts produce nonzero results.
  Existing DerivedData and evidence survive cleanup. Zero-change and edit loops
  remain distinct; missing measurements never become zero-second successes.
- The benchmark implementation has one owner; two compatibility helpers call it.
  Compilation diagnostics preserve failure status and isolated build products.
  Reports require completed runs, omit speculative speedup percentages, and treat
  settings suggestions as hypotheses. Retention requires measured benefit or a
  separately approved non-performance reason.
- Trace capture defaults to 30 seconds, a unique artifact and a run-specific stop
  path. System-wide capture still requires its explicit acknowledgement.
- TesterArmy instructions come from npm e2e 0.17.0, with web 0.12.0 and mobile
  0.9.2. Runtime dependencies are project-scoped. No unattended initializer,
  provider selection, telemetry, upstream feedback or MCP registration is automatic.
  Deterministic tests need no model. Mobile, AI, accessibility and device evidence
  remain separate from a passing browser assertion.
- Codebase Design supplies interface/invariant reasoning when useful. Project
  vocabulary remains authoritative; parallel design agents are optional and routed
  by the existing dispatcher.

Installation inventory proves files and revisions, not that a host has loaded
its discovery cache or authenticated a runtime. Verify actual files inside every
reachable environment; inaccessible cloud environments must remain unverified.

## PStack 0.15.9

The reviewed pin is `e43c7ee26e0038c6c1fa8380dd34ce86ff94cb2a`:
three added and eighteen changed resources, with 140 unchanged. New benchmark and
measurement references are shared by Codex, Cursor and universal Forge. Recurring
error correction extends the existing learning principle rather than adding a
second owner. Architecture guidance reinforces one state owner, generated lists,
private internals and supported caller migration. Existing hypothesis/trace methods
remain in place. Native PStack installation uses the same new pin.

The toolkit retains its draft readiness, review, worker ownership, model qualification,
plan validator and scheduling rules. Upstream ten-lane, hourly-loop, automatic memory
mutation and always-ready-PR defaults were not adopted. The provenance catalog maps
new and changed resources to the maintained local method or an explicit exclusion.
